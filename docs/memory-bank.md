## Локальное окружение (Windows)

| Что | Значение |
|---|---|
| Папка проекта | `E:\Project\END actual` |
| Python | venv 3.12 в `venv/` (`venv\Scripts\python.exe manage.py runserver`) |
| БД локально | SQLite `db.sqlite3` (через `.env`: `DB_ENGINE=django.db.backends.sqlite3`) |
| Фронтенд | `frontend/`, Vite на `http://localhost:3001` (проксирует `/api` на Django :8000) |
| Суперпользователь | `admin` / `admin` |
| PostgreSQL 17 локально | порт 5432 занят, пароль суперпользователя неизвестен — потому SQLite |

`config/settings.py` поддерживает БД через `.env` (`DB_ENGINE/DB_USER/DB_PASSWORD/DB_HOST/DB_PORT/SQLITE_PATH`);
по умолчанию — PostgreSQL, как на серверах (поведение серверов не меняется).

## Правила работы (договорённости с заказчиком)

1. **Деплой — только по явному указанию.** Обычный итог работы — коммит в локальный `main`.
2. Я не делаю скриншотов и проверок в браузере — заказчик проверяет сам и даёт ответ.
3. Если правка затронет бэкенд — предупреждать заранее (из списка аудита это только «срок жизни токена»).
4. Ветки деплоя именуются `deploy-ГГГГ-ММ-ДД[-пометка]` (пример: `deploy-2026-08-25-lang`).

## Флоу деплоя на сервер

```bash
cd /home/sadmin/web/dev          # или prod
git fetch origin
git checkout deploy-ГГГГ-ММ-ДД-…

```
Бэкенд менялся только в части пагинации (см. ниже); gunicorn обычно не трогаем.

## Журнал изменений

### 19–20.08 — запуск и электро-форма

- Репозиторий склонирован, поднят локальный запуск (venv, SQLite, админ).
- Форма наряда на электроустановки (`ElectricalPermitFormNew.tsx`) приведена к дизайну
  наряда повышенной опасности: карточки-секции, степпер, футер, кнопки, единые размеры полей.
  Ветка `feature/electrical-form-ui` → влита в main на стороне сервера (коммит 05e38e5).
- Синхронизация с сервером: в main вернулся бренд «АО „Каражанбасмунай“».

### 20–21.08 — редизайн входа (ветка `feature/login-redesign`)

- Новая страница авторизации «Каспийский горизонт»: сплит-экран, брендовая панель,
  знак ЭНД с ледяным градиентом, форма в общем стиле ЭНД.
- Ротация фото производства: `frontend/public/main.jpg…main6.jpg` подхватываются автоматически,
  смена раз в 3 минуты, кроссфейд 2.5с, синхронный дрейфт зума; `prefers-reduced-motion` учтён.
- Новое лого `logo-kbm.png` (PNG с прозрачностью): на входе и в шапке приложения перед «ЭНД».
- Ключи локалей: `login.title`, `login.tagline`.

### 21.08 — пагинация (perf)

- Бэкенд: `DynamicPageSizePagination` в `permits/views.py` — `?page_size=N` до 200, по умолчанию 20.
- Фронтенд `App.tsx`: первая страница `page_size=100`, остальные — параллельно `Promise.all`,
  упавшие страницы переспрашиваются по одной; кеш списка (рефетч только при пустом списке,
  смене пользователя или после создания/сохранения наряда).
- Диагностика на сервере «грузит 7 страниц»: причина — деплой без этих коммитов.

### 21–22.08 — типографика и элементы интерфейса

- Шкала форм: поля/подписи 18→16→**14px**, навигация 18→**16px**; отступы полей `py-3→py-2`,
  ячеек таблиц `py-2→py-1.5`; подборщики (SearchableSelect/UserSearchSelect) приведены к той же шкале.
- Подчёркивание заголовков секций — графит `slate-900` 2px.
- Степпер по референсу: круги с номерами/галочками, соединители; живёт в шапке формы,
  при прокрутке уезжает вместе с контентом (закрепление сознательно убрано по просьбе).
- Окно уведомлений: редизайн + «живые» уведомления — опрос 30с, мгновенная догрузка при возврате
  на вкладку, тост о новом уведомлении (через `Toasts`), фоновой вкладкой не опрашиваем.
- Список нарядов на главной: строки `py-3`, шрифт таблицы 14px.
- Окно выбора типа наряда (`PermitTypeSelector`): строгий корпоративный стиль, Escape, локализация.

### 23.08 — диалоги и тосты

- `components/ConfirmDialog.tsx`: стилизованный аналог `window.confirm`, promise-API,
  Enter/Esc, фокус на «Отмене» для опасных действий. Заменены все 5 мест.
- `components/Toasts.tsx`: всплывающие уведомления вместо `window.alert` (удаление наряда, ошибки).

### 24.08 — надёжность, рефакторинг, уборка

- `components/ErrorBoundary.tsx`: страховка от «белого экрана» — `AppErrorBoundary` вокруг
  приложения (index.tsx) + `CardErrorBoundary` вокруг карточек наряда в App.tsx.
- `utils/formatPermit.ts`: три копии приведения данных наряда сведены в одну (с отчеством).
- Удалены мёртвые файлы: `CreatePermit_check_list.tsx`, `ElectricalLifecycleView.tsx`,
  `bg-login.png`; вычищены фантомные классы `animate-in …` (плагин не установлен).
- Деплой-ветка `deploy-2026-08-24`.

### 25.08 — раздельные языки в электро-форме

- 147 надписей формы заполнения вынесены в словарь `electrical.*` (ru.json/kk.json):
  форма целиком на выбранном языке, включая кнопки, степпер, футер, шапку страницы.
- Казахские тексты взяты из существовавших двуязычных пар + словаря; ничего не выдумано.
- Намеренно остались двуязычными: журнал допуска (режим просмотра) и справочные названия
  (организация, «Электроцех», «ЦДН», категории работ).
- Деплой-ветка `deploy-2026-08-25-lang`.

### 27.08 — производительность, UX-полировка, первые тесты

- **Ленивая загрузка**: тяжёлые экраны (карточка наряда, формы, LOTO, статистика, задачи, ИИ)
  и карта (maplibre, 1.3 МБ) вынесены в отдельные чанки. Главный чанк: **2445 → 369 КБ** (gzip 597 → 111).
  Загрузка — со скелетонами вместо спиннеров (`components/Skeleton.tsx`).
- **Фокус-ловушки** (`hooks/useFocusTrap`) для модалок ConfirmDialog и PermitTypeSelector.
- **useMemo** фильтров дашборда (не пересчитываются на каждый рендер).
- **Общий степпер** `components/Stepper.tsx` — дедупликация из двух форм.
- **formatPermit**: типизирован `RawPermit` (было `any`).
- **Тесты**: vitest + @testing-library (5 тестов: formatPermit, Stepper), запуск `npm test`.
- ⚠️ **Открыто (№2 DOCX у электро)**: обнаружено, что кнопка «Создать наряд» электро-формы
  **не сохраняет данные на сервер** (данные живут только в браузере; category в API отсутствует).
  Кнопка DOCX отложена до проводки сохранения — фактически это начало модуля по ТЗ.
