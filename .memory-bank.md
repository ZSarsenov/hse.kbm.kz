### Модели данных

**User** (`users.User`) — кастомный AbstractUser:
- `iin`, `bin`, `tabel_number`, `position`, `surname` (отчество), `role`, `company_name`, `department` (FK)

**WorkPermit** (`permits.WorkPermit`) — основной наряд:
- `permit_id` (OR-2026-XXXXX), `status` (FSM), `initiator` (FK), `template` (FK), `location` (FK)
- `valid_from`, `valid_to`, `data` (JSONField — все поля формы)
- `scan_file` (FileField), `safety_document` (FileField), `loto_photo` (FileField)
- `producer_closed` (Boolean), `verify_token` (UUID)

**ApprovalStep** (`permits.ApprovalStep`) — цепочка подписания:
- `permit` (FK), `approver` (FK, nullable для внешних), `step_order`, `role`, `status`
- `signed_xml`, `signer_details` (JSON), `rejection_reason`, `signed_at`

**WorkPermitTemplate** — шаблоны нарядов (`name`, `description`, `is_active`)

**Location** — участки/цеха (`name`, `latitude`, `longitude`, `department` FK)

**Department** — подразделения (`name`, `name_kk`)

**DangerousWorkType** — виды опасных работ (`name`, `name_kk`, `color_code`)

**Notification** — уведомления (`user` FK, `title`, `message`, `is_read`, `permit_id`)

**AuditLog** (`core.AuditLog`) — аудит (`user` FK, `action`, `details`, `timestamp`)

### Статусы наряда (django-fsm FSM)
```
DRAFT → PENDING_APPROVAL → APPROVED → CLOSED
  ↑         ↓ reject()
  └─── REJECTED ←──┘
```

### Цепочка подписания (генерируется при отправке)
1. **ISSUER** — Выдающий наряд
2. **RESPONSIBLE** — Ответственный руководитель
3. **ADMITTING** — Допускающий
4. **WORK_PRODUCER** — Производитель работ (ЭЦП или граф. подпись)
5. **COORDINATOR(s)** — Согласующие (до 5 доп. + 1 основной; основной может быть внешний с граф. подписью)

### Роли пользователей
`ADMIN`, `AUDITOR`, `ISSUER`, `WORK_PRODUCER`, `ADMITTING`, `COORDINATOR`, `RESPONSIBLE`

## REST API (базовый URL: /api/v1/)

### Аутентификация: Token-based
```
POST /api/v1/api-token-auth/
  Body: { username, password }
  Response: { token, id, username, name, email, role, company, department, position, is_admin, is_auditor }
```

### Эндпоинты

| URL | ViewSet | Действия |
|---|---|---|
| `/api/v1/permits/` | WorkPermitViewSet | CRUD + submit/sign/reject/duplicate/producer_signature/supervisor_signature/brigade_signature/add_brigade_member/producer_close/close/download_pdf/download_docx/verify_docx/upload_safety_document/upload_loto_photo/delete_loto_photo + my_tasks/audit_stats/export_journal |
| `/api/v1/templates/` | WorkPermitTemplateViewSet | Только чтение |
| `/api/v1/departments/` | DepartmentViewSet | Только чтение + поиск |
| `/api/v1/work-types/` | DangerousWorkTypeViewSet | Только чтение |
| `/api/v1/notifications/` | NotificationViewSet | Список + mark_read |
| `/api/v1/users/` | UserSearchViewSet | Поиск активных пользователей |
| `POST /api/v1/ai-chat/` | — | Чат с DeepSeek AI |
| `GET /api/v1/verify/{uuid}/` | — | Публичная верификация (без авторизации) |

### Ключевые настройки DRF
- Аутентификация: `TokenAuthentication`
- Права: `IsAuthenticated`
- Пагинация: `PageNumberPagination` (page_size=20)
- CORS: `127.0.0.1:3000`, `localhost:3000`, `10.60.2.89:3000`
- ALLOWED_HOSTS: `['*']`
- AUTH_USER_MODEL: `users.User`
- Auth Backend: `CaseInsensitiveModelBackend` (без учета регистра)

## Ключевые фичи

1. **ЭЦП через NCALayer** — подписание XML с ГОСТ-криптографией (lxml + cryptography)
2. **Графические подписи** — для внешних согласующих и производителей работ (react-signature-canvas)
3. **QR-верификация** — публичная проверка подлинности наряда по QR-коду
4. **AI-ассистент** — DeepSeek чат-бот для консультаций по HSE
5. **Генерация DOCX/PDF** — docxtpl + LibreOffice + reportlab
6. **XLSX экспорт журнала** — openpyxl
7. **Локализация** — казахский + русский (i18next)
8. **LOTO** — фото блокировки/маркировки оборудования
9. **Документы безопасности** — загрузка PDF/JPG
10. **Дублирование нарядов** — клонирование в новый черновик
11. **Журнал нарядов** — с колонкой "Цех"
12. **Аудит и статистика** — дашборд для AUDITOR с топ-локациями, временем закрытия
